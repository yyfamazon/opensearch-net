    ErrorCauseConverter<TErrorCause>

    System.Text.Json replacement for the legacy Utf8Json ErrorCauseFormatter<T>.

    Reads an ErrorCause that OpenSearch may return either as a bare string (treated as the Reason) or as an object with a fixed set of snake_case fields; unrecognised fields are collected into AdditionalProperties. caused_by is recursive. Derived types extend the known-field set via the ReadExtraField(ref Utf8JsonReader, string, TErrorCause, JsonSerializerOptions) / WriteExtraFields(Utf8JsonWriter, TErrorCause, JsonSerializerOptions) hooks.

    ErrorConverter

    System.Text.Json replacement for the legacy Utf8Json ErrorFormatter. Extends ErrorCauseConverter<TErrorCause> with the two Error-specific fields: headers and root_cause.

    ExceptionConverterFactory

    A JsonConverterFactory that serializes any Exception (and derived types) as a JSON array, one object per exception in the InnerException chain. This replaces the legacy Utf8Json ExceptionFormatter<TException> and its resolver.

    Like the legacy formatter, this reads exception state via ISerializable.GetObjectData, so RemoteStackTraceString and RemoteStackIndex are still emitted and the output matches the legacy engine field-for-field. The one field the legacy formatter emitted that this does not is the structured ExceptionMethod object; on modern .NET GetObjectData no longer populates the underlying ExceptionMethod serialization entry, so the legacy formatter also produces nothing for it in practice (verified byte-for-byte across several exception shapes). Serialization is one-way; deserialization is not supported, matching the legacy behaviour.

    GenericDictionaryConverterFactory

    Handles dictionary types that System.Text.Json's built-in dictionary support cannot: those keyed by object (STJ rejects a non-string/non-primitive dictionary key) and read-only dictionary types that lack a public parameterless constructor (e.g. ReadOnlyDictionary<,>, a custom IReadOnlyDictionary<,>, or an IIsADictionary implementation). Keys are written verbatim via ToString; values delegate to the surrounding options. On read the target concrete type is reconstructed through a parameterless constructor + indexer, or a constructor accepting an IDictionary<TKey,TValue>.

    The common string-keyed cases (Dictionary<string,T>, IDictionary<string,T>, Hashtable) are left to STJ's built-in support — CanConvert(Type) only claims the types STJ fails.

    InterfaceDataContractResolver

    A System.Text.Json IJsonTypeInfoResolver that reproduces the legacy Utf8Json [InterfaceDataContract] behaviour: serialization metadata (DataMemberAttribute / IgnoreDataMemberAttribute) is frequently declared on the interfaces a request type implements rather than on the concrete class. When a type (or one of its interfaces) is marked with OpenSearch.Net.Utf8Json.InterfaceDataContractAttribute, this resolver:

    • opts the type into a data-contract model: only members carrying DataMemberAttribute (on the property or a matching interface property) are serialized;
    • honours IgnoreDataMemberAttribute and the Name of DataMemberAttribute as declared on the interface.

    This is the System.Text.Json replacement for the metadata handling in the legacy MetaType.

    Iso8601DateTimeConverter

    System.Text.Json replacements for the legacy Utf8Json ISO8601DateTimeFormatter / ISO8601DateTimeOffsetFormatter (the default DateTime/DateTimeOffset handling of the old engine).

    System.Text.Json's built-in Utf8JsonReader.GetDateTime() only accepts a strict RFC 3339 / ISO 8601 extended profile: it rejects the ISO 8601 "basic format" numeric offsets OpenSearch emits and accepts (+1000, +10) and it caps fractional seconds at 7 digits. The legacy formatter parsed those forms, so relying on the built-in reader regresses real payloads (see GitHub issue #4876) with "The JSON value is not in a supported DateTime format." This converter reproduces the legacy parser exactly.

    Behaviour mirrored from the legacy formatter:

    • Truncated forms: "YYYY", "YYYY-MM", "YYYY-MM-DD".
    • Time to seconds precision, then optional '.' fraction of 1..7 significant digits (ticks); digits beyond the seventh are read and discarded ("lack of precision").
    • Zone: 'Z' (UTC), or a sign followed by an offset of length 3 (+hh), 5 (+hhmm) or 6 (+hh:mm). Any other offset length is an error.
    • DateTime with an explicit offset is normalised to UTC then converted to local time (matching the legacy ...DateTimeKind.Utc).AddTicks(ticks).Subtract(offset).ToLocalTime()); a bare value keeps DateTimeKind.Unspecified (or Utc for a trailing 'Z').
    • Invalid input throws InvalidOperationException with the same message prefix as the legacy formatter, so callers that catch it (e.g. issue #4876's tests) keep working.

    ObjectConverter

    Writes values whose declared (static) type is object — the common case for dynamic request bodies such as Dictionary<string, object> built from a parsed YAML/JSON document. System.Text.Json writes a dictionary's object values through the declared object type, which bypasses the registered DoubleConverter/SingleConverter; an integral double like 3.0 would then be emitted as 3, changing the value the server stores. This converter dispatches on the runtime type so boxed doubles/floats keep their trailing .0 and nested objects/arrays recurse through the same rules.

    On read, System.Text.Json's own object handling (or a more specific converter such as DynamicDictionaryConverter) applies, so this converter is write-only and defers reading to the reader's element deserialization.

    OpenSearchContractAttribute

    Public marker attribute for the System.Text.Json data-contract model, usable on interfaces (unlike the framework's DataContractAttribute). It is the migration replacement for the Utf8Json-internal [InterfaceDataContract]: apply it to an interface (or type) whose DataMemberAttribute annotations should drive serialization via InterfaceDataContractResolver.

    SingleConverter

    SingleOrManyCollectionConverter<T>

    A JsonConverter<T> for IReadOnlyCollection<T> that accepts either a JSON array or a single value. OpenSearch frequently omits the surrounding array when a field holds only one element (e.g. "foo" instead of ["foo"]); in that case the single value is wrapped into a one-element collection. This mirrors the legacy InterfaceReadOnlyCollectionSingleOrEnumerableFormatter<T>.

    StringEnumConverterFactory

    A JsonConverterFactory that produces string-based enum converters for enum types decorated with StringEnumAttribute. Mirrors the legacy Utf8Json EnumFormatter: the serialized name is EnumMemberAttribute.Value, else DataMemberAttribute.Name, else the verbatim enum field name (no camelCasing).

    ValueTupleConverterFactory

    System.Text.Json replacement for the legacy Utf8Json ValueTupleFormatter. A System.ValueTuple exposes its elements as public FIELDS (Item1, Item2, …, and Rest for arity > 7), which STJ does not serialize by default (IncludeFields is off), so a tuple member would otherwise render as an empty object. This factory (de)serializes the tuple as an object with Item1..ItemN properties, matching the legacy formatter, without turning on field serialization globally.
